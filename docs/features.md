# Features in detail

## Import

Everything is read in the browser and opens as a new project (from the start page or by drag and drop).

Dropped into the open editor instead, images land on the slide, `.md` files become decks, and PowerPoint, OpenDocument, PDF and `.slides.json` files are inserted after the current slide (scaled to the project's slide size). Copy and paste of elements keeps their images, also into another project.

- **Slidev project**: pick a folder. Loading starts from `slides.md`, like in Slidev. Decks included with `src:`, images (also from `public/`), the theme, components and `package.json` come along. Slides are rendered and measured with Slidev's layout and UnoCSS rules, so they look as they do in Slidev. Opening the same folder again asks whether to open the existing project, make a copy or overwrite it.
- **PowerPoint (`.pptx`/`.potx`)**, also exports from Google Slides and Keynote, and **OpenDocument (`.odp`/`.otp`)** from LibreOffice Impress:
  - Text boxes, lists, tables, shapes, images, backgrounds, master and layout elements and speaker notes become editable elements at their position.
  - Font size, colour and family, bold/italic/underline and alignment are also taken from layout and master placeholders. Vertical alignment inside a text box is kept and can be changed in the inspector.
  - Rotated, flipped or cropped images, freeforms, arrows and (dashed) connectors come in as images. Fonts named with their weight ("DM Sans Bold"), numbering, bullets and Wingdings symbols are kept.
  - Tables keep column widths, cell colours and cell borders (width, colour, dashed/dotted), also from table styles: styles defined in the file (PowerPoint, Google Slides) and the 74 built-in PowerPoint styles when a file only names one by id.
  - Not imported: rotated text, gradients, animations, embedded fonts (the installed or a fallback font is used), rare shape presets, charts and SmartArt (their fallback image is).
- **PDF**: each page becomes an image slide (not editable), its text goes into the speaker notes.
- **HTML**: Slidecko's own HTML exports (single file or ZIP) contain the project and open without loss. Other HTML files are not supported.
- **Images**: each image becomes a slide, sorted by file name.

Loose `.md` files each become a deck, sorted by name. Decks can be moved by dragging their name in the sidebar, renamed, removed and exported one by one.

## Export

From the Export menu or the export dialog (⌘E), for the whole project or one deck. Hidden slides are left out of every export except Slidev.

- **Slidev (`.zip`)**: a main `slides.md` with `src:` references, one `.md` per deck, images at their original paths. Unchanged slides stay byte for byte (blank lines included); new slides stay plain Markdown while their text and code keep the arrangement of the slide layout (typing is fine; moving, resizing, styling or adding elements is not); edited ones are written as positioned HTML blocks (a `{{` in their text is wrapped in `<span v-pre>` so Slidev does not read it as Vue; code keeps it as is). Themes that stand for a Slidev theme package (such as `themes/jbt.theme.json`) are added as a package dependency; all others ship as `style.css`. The export message names images that the Markdown references but that were not uploaded.
- **PDF**: through the print dialog, one page per slide, text stays selectable. "One page per click step" in the export dialog (also for images; like Slidev's `--with-clicks`) adds a page for every click: before the first click up to all shown. Backgrounds with CSS blend modes that print engines cannot draw are replaced by an image first.
- **PowerPoint (`.pptx`)**: editable text in the font actually used, clickable links, native tables and shapes, images and speaker notes.
  - Line breaks come from the editor (soft breaks in the same paragraph). Nested lists become real outline levels, numbering keeps its start value, columns (flex/grid) become separate text boxes.
  - Backgrounds (gradients, overlays, frames) are rendered once per variant into a slide master.
  - The slide XML follows the OOXML schema (ISO/IEC 29500). A second `<a:pPr>` per paragraph that pptxgenjs writes, against the schema, is removed.
  - Opens in PowerPoint, Keynote, Google Slides and LibreOffice.
- **Google Slides (`.pptx`)**: the same file with line spacing as multiples. Google Slides enlarges fixed spacing by 1.2 and Keynote handles multiples differently, hence two variants.
- **PowerPoint exact (`.pptx`)**: each slide as a 1960 × 1104 px image, with notes. Looks exactly like the editor in every program.
- **OpenDocument (`.odp`)**: editable, for LibreOffice Impress, OpenOffice and Collabora. Comes from the same layout pass as the PPTX.
- **HTML presentation (`.html`)**: one file with all slides, images and fonts. Runs offline in any browser (arrow keys, swipe, F for full screen where the browser allows it, `#12` jumps to slide 12, printable; on touch screens the previous/next buttons stay visible).
- **HTML presentation (ZIP)**: the same as `index.html` with images and fonts as separate files. Smaller, good for web servers and learning platforms.
- **Images (`.zip`)**: one PNG per slide.
- **Fonts in exports**: the HTML presentation and the images embed the included and uploaded fonts the slides or their theme use (nothing else); PDF waits until they are loaded. The Slidev project gets them as files in `public/fonts/` (with the licence of included fonts) and `@font-face` rules in `style.css`, so it needs no network. PowerPoint and OpenDocument cannot carry fonts: they name the font, which must be installed on the computer that opens the file (otherwise a fallback font is shown).

## Editing

- **Text**: pasting from Word, Google Docs or web pages keeps bold/italic/underline, colours, links, paragraphs and lists. In imported text, pasted paragraphs and list items take the font, size, colour, spacing, bullets and indents of the target.
- **Elements**: headings, lists, quotes, callouts, code, images, tables, charts, shapes, Mermaid diagrams, formulas (KaTeX, `$…$` in text), icons, YouTube, timers, random pickers and quizzes.
- **Icon** (Insert → Icon …, ⌘K "Insert icon"): an icon from the Iconify sets Slidev projects use most: Lucide, Tabler, Material Design Icons (`mdi`), Carbon and Phosphor (`ph`), about 28 000 icons. They are bundled with the app (no request to the Iconify servers); each set loads on first use. The picker searches names and aliases in one set or all of them (words in any order, e.g. "arrow right"), shows the first 240 hits and is used with the keyboard: Down from the search field enters the grid, arrow keys move, Enter picks (Enter in the field takes the first hit); it remembers the last set. The icon fills its box (corners keep the aspect ratio); colour is the theme's accent by default, or the theme's text colour or any colour; it turns in quarter turns and flips horizontally or vertically. Double-click or "Change icon …" picks another one and keeps position, size and colour. Icons are decorative (hidden from screen readers) unless they get a description in the inspector; the accessibility check only counts described icons. The project and `.slides.json` keep the icon's name and its SVG, so it still shows if a set is ever dropped. PDF, images and the HTML presentation get it as inline SVG; PowerPoint as an SVG picture in its colour (with a PNG for older readers; the description, else the icon name, as alt text); OpenDocument as an SVG picture. The Slidev export writes Slidev's component in a positioned box (`<mdi-home style="width:100%;height:100%;color:…" />`, turns and flips as CSS) and adds `@iconify-json/<set>` to `package.json`. Importing Slidev Markdown turns an icon tag of these sets that stands on its own line (`<mdi-home />`, `<i-mdi-home />`, `<mdi:home />`, with its `style`, colour class and `aria-label`) into an icon element; icons inside text, of other sets, or with unknown names stay in the slide's Markdown as before.
- **Formulas (TeX)**: in any text box, `$…$` is a formula inside the line and `$$…$$` a centred one, in Slidev's notation; `\$` is a dollar sign. A `$` opens a formula only before a non-space and closes one only after a non-space and not before a digit, so prices like "5 $ and 6 $" or "$5 and $6" stay text, and code never holds formulas. The slide shows them rendered with [KaTeX](https://katex.org); double-click the box and you edit the TeX. Insert → Formula adds a formula of its own (a box with one centred formula): the inspector has the TeX code, a live preview, KaTeX's error message for broken code, starter templates (quadratic formula, sum, integral, matrix, Euler's identity), font size and colour. Markdown imports (Slidev projects, "Insert slides from Markdown", the Markdown tutorial) read `$…$` as formulas in the text and a `$$` block on its own lines as a formula element; the Slidev export writes them back as `$…$` and as a `$$` block in a positioned box (Slidev renders KaTeX itself). HTML, PDF and images show the rendered formulas (the HTML file carries KaTeX's styles and the fonts it uses, so it works offline); PowerPoint and OpenDocument get a formula, or a text box with a formula in it, as a picture with the TeX as alt text. The project file keeps the TeX. Screen readers read KaTeX's MathML; the accessibility check checks a formula's size and contrast like text. KaTeX and its fonts are loaded from the app itself, only when a deck has a formula.
- **Diagram (Mermaid)** (Insert → Diagram): a [Mermaid](https://mermaid.js.org) diagram of any kind Mermaid draws (flowchart, sequence, class, state, gantt, pie, mind map …), in the theme's colours and font. The inspector has the code with a live preview and starter templates (flowchart, sequence, gantt, mind map); broken code shows the error there while the slide keeps the last working diagram. A ```` ```mermaid ```` block in imported Markdown (Slidev projects, "Insert slides from Markdown", the Markdown tutorial) becomes a diagram; the Slidev export writes it back as a ```` ```mermaid ```` block in a positioned box, which Slidev renders itself (in its own size inside the box). PDF, HTML, images, PowerPoint and OpenDocument get the diagram as a picture. Mermaid is loaded only when a deck has a diagram; the drawing is sanitized and runs with Mermaid's strict security level (no clicks or scripts in diagrams).
- **Timer**: a countdown (for example 10:00 for a task in class) or, with duration 0, a stopwatch. While presenting, a click starts or pauses it, a double click sets it back, a run-out countdown blinks and starts over with the next click. It works the same in the HTML presentation export; PowerPoint, OpenDocument, PDF, images and Slidev get its start value as text (Slidev keeps it as a timer for the re-import). The running time is not saved: every presentation starts fresh.
- **Random picker** ("who's next?"): a list of names or groups, one per line in the inspector. While presenting, a click draws one at random and shows it large with how many are left ("3 of 20 left"); nobody is drawn twice until everyone was, then it starts over. A double click starts over at once. It works the same in the HTML presentation export; the editor, PowerPoint, OpenDocument, PDF and images show "🎲 Random pick (20)", Slidev gets the names as text and keeps the list for the re-import. Who was drawn is not saved: every presentation starts fresh.
- **Chart** (Insert → Chart): column, bar, line, pie or donut chart from a small data grid in the inspector: the first row names the series, the first column the categories. Copied cells from Excel, Google Sheets or Numbers paste into it (into the top-left cell they replace the data, elsewhere they fill from that cell on and grow the grid); numbers like `1.234,5`, `1,234.5` or `12 %` are understood. Options: stacked columns or bars, legend, values, a title, fixed axis minimum or maximum (empty = automatic). The first series takes the theme's accent, the others a fixed palette; each series can get its own colour. Labels use the theme's text colour and font. The chart is drawn as SVG, so PDF, images and the HTML presentation get it sharp; PowerPoint gets a native, editable chart; OpenDocument a picture. The Slidev export writes the SVG in the chart's box with the data in `data-chart`, so a re-import brings the editable chart back. Charts in imported PowerPoint files stay pictures.
- **Quiz**: a question with 2 to 6 answer tiles (A–F); the inspector sets the question, adds or removes answers and ticks the correct ones. While presenting, a click on a tile marks it (for example the class's vote), "Reveal" on the quiz or Q shows the correct answers in green and dims the others, a second time hides them. Marks and solution are not saved: every presentation starts fresh. It works the same in the HTML presentation export; PowerPoint, OpenDocument, PDF and images get each quiz slide twice: first as asked, then the same slide with the solution marked. In Slidev the question and answers are text and the next click boxes the correct answers in green (`v-mark`); the quiz itself comes back on re-import.
- **Notes box for the class** (Insert menu or ⌘K): a framed text box with "Editable while presenting" switched on (the switch is in the properties of any text box). While presenting, a click into it lets you type the results of the class right on the slide (the box grows downwards with the text, as in the editor); Enter in a list adds a bullet, Esc ends the typing (a second Esc ends the presentation), and slide keys and clicks inside the box do not change the slide. What you type is saved in the project like a normal edit (undo works) and appears in every export as normal text. In the HTML presentation export the box is read-only. Slidev keeps the switch as `--board:1` in the box style for the re-import.
- **Hand-drawn marks** (Slidev's `v-mark`, Rough Notation): select words while typing and choose the pen button ("Mark") in the text toolbar: underline, circle, box, highlight, strike through, cross out or bracket, in the theme's accent or one of Slidev's 14 mark colours, drawn always or on a click step (the menu lists the slide's steps and the next one; a mark with a step counts as a step of the slide, like `v-click`). With the caret inside a mark the menu changes or removes it. The strokes are drawn from a seed (type, text, position), so the editor, thumbnails, presenting, PDF, images and the HTML presentation look the same, and they follow the text when it reflows (typing, box width, theme, web fonts). The editor shows a mark's step in a small purple badge at its start. While presenting, a mark with a step draws itself along its strokes when its step comes (with reduced motion it just appears); the HTML presentation does the same. The Slidev export writes `<span v-mark.circle.orange="2">` (a palette colour as modifier, any other as `{ at: 2, color: '#e11d48' }`, a mark without step as `v-mark="false"`, which Slidev draws at once); an unchanged imported slide is written back byte for byte. The import reads every type (also the aliases `strike`, `cross` …), colour modifier and option object into editable marks; a bare `v-mark` or `"+1"` takes the click after the slide's previous mark. `delay` and `op` modifiers are not kept. PowerPoint and OpenDocument get each stroke as a freeform line over the text (static, no click animation); a highlight without a click step is the text's own highlight colour in PowerPoint. A highlight is drawn see-through over the text (Slidev draws it behind).
- **Runnable code** (Slidev's `{monaco-run}`): a JavaScript code block with "Runnable (JavaScript)" in its properties gets an output panel below or to the right of the code (side and size in the properties). "Run" in the properties runs it and keeps the output in the element; while presenting, the code runs when the slide is shown ("Run automatically when shown", Slidev's `autorun`) and with the ▶ Run button above the box or ⌘/Ctrl+Enter. A click on the code edits it while presenting; the presentation keeps its code until "Keep changes" saves the edited code and its output, "Reset" goes back to the slide's code. The panel shows `console.log`/`info`/`warn`/`error`, the value of the last expression (`← …`) and errors with their line (`✖ …`); top-level `await` works, and timers are waited for. A run is stopped after 3 seconds (an endless loop shows "Stopped after 3 seconds"); the output keeps at most 200 lines and 20,000 characters. The code runs in a sandbox: a hidden iframe (`runner.html`, `sandbox="allow-scripts"`, so an opaque origin) that starts a fresh worker for each run, with its own Content Security Policy (`unsafe-eval` only there, `connect-src 'none'`). The code cannot reach the app, its projects (IndexedDB), localStorage or cookies, and cannot load anything from the network. TypeScript (`ts`) runs as JavaScript: type annotations are a syntax error. The HTML presentation export can run the code too (Run button, same sandbox as a `srcdoc` iframe, the code as on the slide); PDF, images, PowerPoint and OpenDocument show the code and the last kept output as text. The Slidev export writes the fence as Slidev does (` ```ts {monaco-run} {autorun:false, lineNumbers:'on'} `; highlighted lines do not combine with it), Slidev's default `monaco: true` is enough, and the import reads it back. The kept output is not part of the Slidev source, so running code does not mark an imported slide as changed.
- **Code**: syntax highlighting, optional line numbers and Slidev's highlighted lines (`{2,4-5}`, the other lines dimmed, also in the PPTX export) and **highlight steps** (`{1|3-4|all}` in the "Highlight lines" field: each click while presenting moves the highlight to the next step, see below). Background colour, opacity and corner radius are adjustable. On a dark background, text and syntax colours switch to a dark scheme, also in the Slidev, PPTX and ODP exports.
- **Tables**: 8 presets, add rows and columns with the plus/minus buttons on the table, drag column widths, paste from Excel, Numbers, Google Sheets, Word or Google Docs (with formatting, links, line breaks and cell colours).
  - Select several cells (⇧-click, drag, ⇧+arrows) and fill them together. Typing replaces all; pasting fills all with one value or repeats a matching block like in Excel.
  - Colour, border, align, clear, copy, sort, or delete the selected cells' rows and columns.
  - Cell colours for a cell, row or column. Cell borders for a cell, row, column or the table (all, outside, inside or single sides, with width, style and colour); the buttons show existing lines and a second click removes them. Kept in all exports.
- **Inspector** (right panel), laid out like a graphics program or word processor: sections with an icon that fold away (Effects and Tips start folded; this is not saved), a text toolbar (paragraph style menu, font and size, B/I/U/S, link, code, text colour, alignment, lists, vertical alignment), colour chips that show the current colour and open the palette, X/Y/W/H fields with a lock button, and Arrange buttons for front, forward, backward and back, alignment, distribute (3 or more) and group/ungroup.
- **Text styles** in the paragraph style menu, with a live preview in the theme, and your own style presets. Text boxes and code blocks grow with their content.
- **Font for all slides**: with nothing selected, the inspector sets the sizes for text, titles and code across the project, in every theme and in the Slidev export (`style.css`).
- **Layout tools**: snapping guides to the slide's edges, margins and centre and to other elements, equal spacing (a moved box snaps to the gap between two boxes in its row or column, after, before or centred between them, and the matching gaps show their size; Alt turns snapping off), with the position (while moving) or size (while resizing) shown under the box, format painter (⌘⌥C / ⌘⌥V: only what both elements have), multi-selection (common font, size, alignment, colours; "Mixed" shows differing values), groups (⌘/Ctrl+G groups the selected elements, ⇧⌘/Ctrl+G ungroups; a click on a member selects the whole group, which then moves, aligns, copies and deletes like a multi-selection; double-click edits one member; kept in the project, `.slides.json` and the Slidev project, not in PowerPoint, ODP or HTML exports), outlines and shadows (in all exports), position lock (kept in the Slidev project), background opacity, align and distribute, horizontal and vertical text alignment, copy and paste, undo and redo (an undo jumps to the slide it changes and selects the changed elements).
- **Find and replace** (⌘F, ⌥⌘F): searches text, tables, code and speaker notes, in the slide, the deck or the whole project, with case, whole word and regular expressions (⌥⌘C/W/R, `$1` groups in the replacement); hits are marked on the slide and in the slide list. "All" in the whole project also replaces in the master and the layouts.
- **Slide presets** and **13 built-in themes**.
- **Master and layouts** (View → Edit master and layouts, ⌘K, or "Edit layouts …" in a slide's layout list): the slide list shows the master and the project's layouts, and the canvas edits their elements with all the usual tools; a banner "Editing master and layouts · Close" shows the mode. The master's elements (logo, footer, slide number) are drawn behind every slide; "Hide master elements" in a slide's properties switches them off for that slide. A layout (slide type) has a name, the Slidev layout it is based on and elements; the panel says what it becomes in Slidev (its own `layout: <name>` once it has a drawn element, otherwise the base layout): those marked "Placeholder" are copied into a new slide made from it (New slide lists the project's layouts with previews), the others are drawn behind every slide using it. Add a blank layout, duplicate, rename or delete one (its slides keep their content and get the default layout, after a confirmation). Changing a slide's layout keeps its content. Fields show the slide number, the slide count (hidden slides included) or the project title ("+ Slide number" etc. in the panel insert a text box with one). New projects start with the former slide presets as layouts; older projects get them on opening, plus one layout per other Slidev layout their slides use. Master and layouts are saved with the project and in `.slides.json`, take part in undo and snapshots, and are in every export: PDF, PowerPoint, ODP, HTML and images draw them as normal elements. The Slidev export writes the master as `global-top.vue`, drawn over the slide because Slidev's bottom layer would sit behind the slide's background (slide number as `$nav.currentPage`, count `$nav.total`, title `$slidev.configs.title`; `hideMaster: true` in a slide's frontmatter hides it) and each layout with drawn elements as `layouts/<name>.vue` (its Slidev layout as a CSS class, the elements behind `<slot />`), used by its slides as `layout: <name>`; layouts without drawn elements stay plain (`layout: cover` …), so unchanged slides stay byte for byte. Importing that project again brings the master and layouts back as editable elements (the `.vue` files carry them in a comment); images in them do not come back. Timers, pickers and quizzes on the master or a layout are not written to the Slidev files.
- **Keep font sizes when switching themes** (on by default): the new theme takes colours and fonts but keeps the previous sizes, so boxes and line breaks stay. Switching back undoes it. A theme switch never changes stored box sizes.
- **Reset to the imported state**: an imported slide (or all changed ones) is re-rendered from its original Markdown and is then exported unchanged again.
- **Markdown**: "Insert slides from Markdown" (⇧M) takes Slidev Markdown, for example generated by an AI. "Edit this slide's Markdown" (M) edits one slide as text, with syntax highlighting. ⌘/Ctrl+Enter applies; Esc after edits asks before discarding them. Raw HTML in the Markdown is sanitized (no scripts, event handlers or `<style>` blocks).
- **Markdown source editor** (File → Edit Markdown source …, ⌥M, ⌘K "Edit all Markdown"): the whole project as Slidev Markdown in a full-window code editor that looks like VS Code (Light+/Dark+ with the app's light/dark switch). One tab per deck file (`slides.md` and the decks it includes). CodeMirror with line numbers, folding, search and replace (⌘F), multiple cursors, bracket closing and undo per tab; highlighting for Markdown, HTML in it, the code blocks' languages and Slidev's slide frontmatter (`---` always separates slides, a `key: value` block after it is that slide's frontmatter). [markdownlint](https://github.com/DavidAnson/markdownlint) checks each slide body while you type (warnings in the gutter and underlined, ⇧⌘M opens the problems list, the status bar counts them and jumps to the first; rules that do not fit slides are off: one h1 per document, inline HTML, line length, first line a heading, duplicate headings); its messages are in English. Format (⇧⌥F) runs [Prettier](https://prettier.io) on each slide body and leaves frontmatter and separators alone. A preview beside the text shows the slide under the cursor, live as you type (below the text on phones). Apply (⌘/Ctrl+S) changes the slides: slides whose text is unchanged stay exactly as they are (free positions, ids, everything Markdown does not carry); edited and new slides are imported like "Insert slides from Markdown", images named by their project path keep their pictures, and slide numbers in links mean the numbering before applying. Undo in the app takes an apply back. Esc or ✕ with changes not applied asks: apply and close, discard, or keep editing. The editor, markdownlint and Prettier are loaded only when it is opened.
- **Markdown tutorial** (start page, File menu, ⌘K "Markdown tutorial"): 10 short lessons – headings, bullet list, bold/italic, numbered list, new slide (`---`), layout via frontmatter, code block, links, table, speaker notes – and a final challenge (a talk with 3 slides, with a stopwatch). You type on the left; the right side shows the real slides, rendered as "Insert slides from Markdown" would. Each lesson checks the result itself and then unlocks Next; Hint and Show solution help, solved lessons can be revisited. The closing screen compares what you typed (characters, lines) with what you got (slides, elements) and opens your talk as a new presentation. Progress is not stored.
- **Links to slides**: the link dialog (⌘K in a text, or the link button) has "Link to" with "Web address" and every slide ("Slide 3: Title"). Shapes and images get "On click while presenting, go to" in Effects; the editor marks them with "→ 3". Links point to the slide itself, not its number, so they follow it when slides are moved; a link to a deleted slide does nothing (the inspector says "a deleted slide") and becomes plain text in Slidev. While presenting and in the HTML presentation a click jumps to the slide; the PDF gets internal links, PowerPoint slide jumps (`ppaction://hlinksldjump`), OpenDocument jumps to the page ("Slide 3"). The Slidev export writes `<Link to="3">` (shapes and images: `@click="$nav.go(3)"`) with the numbers of that moment (hidden slides are not counted, as in Slidev), also in unchanged slides; the import reads `<Link to>`, `[text](/5)` and `[text](#5)`. Slide jumps in imported PowerPoint or ODP files are not read.
- **Table of contents** (Insert → Table of contents): the slide titles as a nested list of slide links, updated as you edit. A title is the frontmatter `title:`, else the slide's first heading (its level counts). Options: from level, to level, columns (1–4), highlight the current slide. Hidden slides and slides with "Hide in table of contents" (slide properties, Slidev's `hideInToc: true`) are left out. Slidev gets `<Toc>` with `minDepth`, `maxDepth` and `columns`; PDF, HTML and images show the list, PowerPoint and OpenDocument a text box with slide jumps.
- **Background image** (slide properties): choose, replace or remove a picture behind the slide, filling it or shown whole, with "Darken" (0–90 %) for readable text; theme backgrounds stay under it. The Slidev export writes `background:` (plus `backgroundSize: contain`, `backgroundDim:`) and copies the file; Slidev shows it in layouts that use `background`, such as `cover`. PowerPoint and OpenDocument get it as the slide's background picture; PDF, HTML and images draw it. The accessibility check asks you to check text over it by eye. "Slidev classes" keeps Slidev's `class:` frontmatter for the export (not applied in the editor).
- **Hide slides**: "Hide slide" in a slide's context menu (or "Hide/show slide" in ⌘K) dims it in the slide list with a crossed-out eye. Hidden slides are skipped when presenting (typing their number still shows them) and left out of PDF, PowerPoint, ODP, HTML and image exports. Slidev's `hide: true` (or `disabled: true`) in a slide's frontmatter imports as hidden; the Slidev export keeps hidden slides with `hide: true`. In PowerPoint files, slides marked hidden (`show="0"`) import as hidden.
- **Slide list**: hover a thumbnail to hide/show, duplicate or open more actions (on touch screens these sit on the current slide). The New slide button has a layout picker next to it, and the panel head has New slide and New deck. With one deck the list shows only the slides; deck rows and their "⋯" menu (also on the main deck) appear once there are several.
- **Sidebars** can be folded away with the arrows at the canvas edges, from the View menu or with ⌥B (slide list) and ⌥E (properties).
- **Zoom**: ⌘= and ⌘− zoom the canvas, ⌘0 or ⇧1 fit it to the window, ⇧0 shows 100 %. ⌘/Ctrl+scroll (or a trackpad pinch) zooms at the pointer; the zoom control in the toolbar has −, the % (a menu with fit, 100 % and 200 %) and +; on phones the % at the bottom right cycles fit, 100 % and 200 % while zoomed. A zoomed slide scrolls.
- **Toolbar and menus**: the toolbar has New slide, Text, Image, Table, Shape (a grid of shapes), Insert, Undo/Redo, zoom, theme, format, export and Present. The menu bar has File, Edit, Insert (every element with its shortcut), Arrange (order, group, align, distribute for the selection) and View (presenting, zoom, panels).
- **Version history** (File → Version history): while you edit, the state before your changes is kept as a snapshot at most every 10 minutes; "Save snapshot" (also in ⌘K) keeps one by hand. Up to 20 per project, the oldest are dropped. The list shows time and slide count; "Restore" first keeps the current state as a snapshot, and Undo also takes a restore back. Snapshots stay in this browser (not in `.slides.json` or copies) and are deleted with the project. If the browser storage is full, only the snapshot fails, the project is still saved.
- **Shortcuts**: ⌘K or `?` lists every command with its shortcut.
- **Product tour**: on the first visit (no projects yet) the start page offers "1-minute tour" and "Full tour incl. Markdown (~5 min)"; ⌘K "Take the tour" / "Full tour …" and Edit → Take the tour start it any time. Coach marks highlight the real controls (slide list, slide, Insert menu, properties, theme, present, export, command search) with Back/Next/Skip and "3 of 9"; the page stays usable underneath, and one step asks you to double-click the title and type your name, then moves on by itself. Arrow keys step, Esc ends it; steps whose control is hidden (folded panel, phone layout) are left out. From the start page the tour makes a sample project "Tour" (removed again if you skip on the first step). The full tour hands over to the Markdown tutorial and, once its talk is opened as a new presentation, ends with three marks there (present, export, Edit Markdown).

## Fonts

- **Font choice**: the font menu of a text box (and the theme editor's font fields) lists system fonts, fonts included with Slidecko and the project's own fonts, each shown in its face.
- **Included fonts**: Inter, Montserrat, Nunito, Source Serif 4, Lora, Playfair Display and Fira Code (SIL Open Font License, Latin and Latin Extended, variable weights, with italics except Fira Code). They come from Slidecko's own server and only when a slide uses them; no font is loaded from other servers.
- **Own fonts**: "Add font file …" at the end of the font menu adds a `.woff2`, `.woff`, `.ttf` or `.otf` file (at most 5 MB; checked by its content, not its name) to the project and applies it. It is stored with the project in the browser, travels in the `.slides.json` and is removed with the trash button next to the menu. A text box whose font is not in the project (pasted from another project, removed font) shows the theme font.

## Theme editor

Colours, fonts and your own CSS (`&` is the slide) with a live preview. CSS that would reach outside the theme (an unbalanced `{` or `}`) is not applied or saved. Built-in themes stay unchanged; changes to them are saved as a new theme. Your themes live in the browser, travel inside the project file and can be exported and imported as `.theme.json` (Theme menu → Import …). Importing a theme again replaces the stored copy; projects keep their theme. The CSS field is a code editor (CodeMirror) with line numbers and highlighting.

## Presenting

Full screen (P or F5) and a presenter view with notes, the next slide and a timer (⌥P). Links are clickable and videos play.

**Slide transitions**: none, fade, slide left or slide up (Slidev's `fade`, `slide-left`, `slide-up`). With nothing selected, the inspector sets a project default and a slide's own transition ("Project default" follows it). As in Slidev, a slide's transition plays between it and the next slide, reversed when going back. Used in full screen, the presenter view and the HTML presentation export; off when the system asks for reduced motion. The Slidev export writes `transition:` in the headmatter (project default) and in the slide frontmatter (own transition), and the import reads both; Slidev transitions the editor does not offer (such as `slide-right`) stay in the frontmatter as written. Slide 1's frontmatter is the headmatter, so in the Slidev export slide 1 always uses the project default. PowerPoint gets fade or push as the next slide's entrance; ODP, PDF and images have no transitions.

**Magic move** (a transition like Keynote's Magic Move or PowerPoint's Morph): elements that are on both slides glide from their place and size on one slide to those on the next, blending colour, fill and font size; the other elements of the old slide fade out and the new ones fade in. Going back plays it the other way. Elements pair up by their "Magic move name" (Effects, single element; only elements with the same name pair), otherwise automatically: same type with the same text, picture, shape kind or code, the nearest first. A duplicated slide's elements stay paired with the original's even after their text changes. Click steps play as usual; Magic move only runs between slides (in full screen, the presenter view, on phones and in the HTML presentation export). With reduced motion the elements only fade. "Preview transition" in the slide properties plays it on the canvas into the next slide. Exports: PowerPoint gets its Morph transition (PowerPoint 2016 and later pair the shapes itself and ignore the names; older versions fade); Slidev gets `transition: fade` plus `slidecko-transition: morph` (ignored by Slidev, read back on import) and `--morph:name` in the element's style; ODP, PDF and images have no transitions.

**Appear on click** (Slidev's `v-click`): any element can be set to appear on click with an order number in the inspector (for a multi-selection, for all of them; switched on, it gets the number after the slide's last one). While presenting, next (→, space, click, swipe …) first reveals the next step, then goes to the next slide; back hides the last step, then goes to the previous slide, which arrives with all its steps shown. Elements with the same number appear together; gaps in the numbers do not cost a click. Elements not revealed yet are invisible but keep their place. The editor shows every element, with the number in a small badge. The presenter view shows the step count (such as "· 2/3") and the state after the next press as "Next slide". The HTML presentation does the same; PDF, images and printing show the final state, or one page per step with "One page per click step".

**Disappear on click** (Slidev's `v-click.hide`): the button under "Appear on click" hides the element from that click on; with both, the element is visible only in between (Slidev's range `v-click="[2, 4]"`). The badge shows "–4" or "2–4". "Together with the previous click" (Slidev's `v-after`) is simply the same number. **Code highlight steps** (Slidev's `{1|3-4|all}`): every further step takes one click, from the block's own click number on (it appears with the first step) or, without one, after the slide's numbered steps. The editor shows the first step (marking lines in the block changes that step), the static exports the last one. **Notes per click**: Slidev's `[click]` and `[click:3]` markers in the speaker notes split them; the presenter view shows the part for the current step in full and the others faded, and scrolls to it. The markers stay in the notes as written, so every export keeps them.

What each format gets: the HTML presentation steps through appear, disappear, ranges, list items and code steps like the editor. **PowerPoint and OpenDocument** get click animations: each element appears ("Appear") or vanishes ("Disappear") on its click; a list shown item by item appears as a whole at its first item's click, code steps show the last step's lines (no click), so these files can have fewer clicks than the editor. The **Slidev** export writes `v-click="2"`, `v-click.hide="3"` and `v-click="[2, 4]"` on the element's box with its step and keeps code steps in the fence (`{1|3|all}`); the import reads them back, also `v-after`, relative steps (an empty `v-click`, `v-click="+1"` or `"'+1'"`, ranges with a relative end such as `['+1', '+2']`) and a `<v-click>` / `<v-click hide>` / `<v-after>` around exactly one element. Slides imported and not changed since are written back byte for byte. In Slidev, code steps count as clicks in the order of the slide's Markdown; in Slidecko a code block without its own click number takes its steps after the numbered ones, so mixed slides can step in another order there. A text box with a list can also show its **list items one by one** (checkbox under "Appear on click"): while presenting, its top-level items (across all its lists) appear one per click, from the box's click step on (without one, after the slide's last step); every item counts as a step, so later steps move back. The editor and the static exports show all items. The Slidev export wraps each such list in `<v-clicks at="n">` and writes every `v-click` as its step, so Slidev counts the same; the import reads a `<v-clicks>` around lists back into this option (other `<v-clicks>`, e.g. with `every` or `depth`, stay in the Markdown for Slidev, and in Slidecko their items appear all at once).

While presenting: type a slide number and Enter to jump there, B or . turns the screen black and W or , white (any slide change ends it), R or a click on the timer resets the timer. Q shows or hides the solution of the quizzes on the slide.

**Laser pointer and pen**: L (or the button in the presenting bar) turns the mouse pointer into a glowing red dot; D draws freehand strokes on the slide with mouse, pen or one finger, A draws a straight arrow (drag from start to tip). While drawing, the bar offers five colours (red, yellow, green, blue, white: readable on light and dark slides) and three line widths. E or C clears the drawing, Esc first puts the tool away and only then ends presenting (in full screen only Chromium browsers let a short Esc through; elsewhere Esc leaves full screen as usual). While a tool is on, clicks and swipes do not turn the slide. The drawing is kept in slide units, so it stays in place when the window or the presenter view changes size; it belongs to the shown slide only, disappears on any slide change and is not saved. The HTML presentation export has the same laser, pen and arrow (L, D, A, E) with the same colours and line widths.

**Rehearsal** (View → Rehearse the talk, or ⌘K "Rehearse the talk"): the presenter view from slide 1 with the total time, the time on the current slide (click steps count toward their slide; going back adds to a slide's time) and, when planned, the planned times with "On track" or "Behind plan" and how far; a slide's clock turns amber at 80 % and red past its planned time. Pause/Resume, Restart (also R: back to the first slide, times from zero) and End rehearsal (also Esc); the other presenting keys work as usual. **Planned times** are set in a slide's properties ("Planned time": this slide, and the whole talk) in minutes or m:ss; the talk length is shared equally by the shown slides without their own time. After ending, a summary shows the total against the plan and a table per slide (actual, planned, difference with sign, the previous rehearsal, a small bar with the planned time as a mark; over-time rows in red), with "Use these times as planned times" (an undoable edit), "Rehearse again" and "Close". The last 5 rehearsals are kept with the project (also in `.slides.json`; compared by slide position). The Slidev export writes the talk length as Slidev's headmatter `duration:` (e.g. `20min`, used by Slidev's own timer) and a slide's time as `plannedTime: 90` (seconds) in its frontmatter, which Slidev ignores; the import reads both back, and unchanged values stay as written.

**Slide overview** (Slidev's `o`): O, G or the grid button in the presenting bar shows all slides as thumbnails, in full screen and in the presenter view. The current slide is framed, hidden slides are dimmed with a crossed-out eye and their number. Arrow keys (Home/End, Page Up/Down) move the focus, Enter or a click/tap jumps there, typing a number (such as 1 2) moves the focus to that slide and Enter jumps; Esc, O or G closes it and keeps the slide. On a phone the thumbnails sit two per row.

**Recording** (Slidev's camera and screen recording): "Record presentation …" in the View menu or ⌘K starts presenting and opens the recording dialog; the record button in the presenting bar opens it while presenting. It records either the presentation itself (the browser asks to share this tab; the video shows exactly what the tab shows, including drawing, laser and the camera bubble) or only the camera (the only choice where the browser cannot share the screen, such as on phones). Microphone and camera can be switched on or off, each with a device choice (the names appear once the browser was allowed access). With the camera on, a round camera bubble sits on the slide while presenting, also before recording starts, so the speaker sees it: small, medium or large, in a corner of choice or dragged anywhere. While recording, the bar shows a blinking red dot with the duration, pause/resume and stop; stopping, "Stop sharing" in the browser or ending the presentation saves the video as a file named after the project and the start time ("My talk 2026-11-24 14-05.mp4"): MP4 where the browser records it (Chrome, Edge, Safari), otherwise WebM (Firefox). The video stays on the device; nothing is uploaded. Blocked or missing camera, microphone or screen sharing get a clear message in the dialog. The last choices (source, devices, bubble size and place) are remembered in the browser.

**Keys while presenting**: ? or H (or the keyboard button in the presenting bar) shows this list on screen, Esc or a click closes it.

| Key | What it does |
| --- | --- |
| → Space Enter / ← Backspace | next / previous step or slide |
| Home / End | first / last slide |
| a number, then Enter | jump to that slide |
| P | presenter view on or off |
| O or G | slide overview |
| B (or .) / W (or ,) | black / white screen |
| R | reset the talk timer (rehearsal: restart) |
| Q | show or hide the quiz solution |
| L / D / A | laser pointer / draw / arrow |
| E (or C) | erase the drawing |
| ? or H | list of these keys |
| Esc | put the tool away, then end presenting |

The letters follow what they do: **L**aser, **D**raw, **A**rrow, **E**rase, **B**lack, **W**hite, **R**eset, **Q**uiz, **P**resenter, **O**verview, **G**o to.

## Phone and tablet

- Up to 760 px wide the app becomes one column that fills the screen without page scrolling: menus and one toolbar row (undo/redo stay at the left, Present at the right, the other tools scroll in between), the slide at full width, a horizontal slide strip (New slide and New deck fixed at its left, the strip fades out where more thumbnails follow; several decks show as compact headers), and the properties as a panel below that scrolls on its own. "Properties" folds the panel away so the slide gets the room; selecting an element opens it again at the top. Language and light/dark are on the start page there.
- On touch screens buttons and handles are larger (handles keep their screen size at any zoom). Two fingers pinch-zoom the slide (a pinch started while dragging puts the element back), a double tap beside the slide fits it again. A second tap on the selected element starts typing, a long press opens the context menu (also on iPhone and iPad, where Safari has none).
- When presenting, a swipe changes the slide, a tap on the left edge goes back one slide, double taps do not zoom and the controls stay visible.
- Phones held sideways (up to 500 px high) get the phone layout too, but scroll as a page; content stays clear of the notch.
- Form fields are 16 px on touch screens so iOS does not zoom in.
- The app asks the browser to keep its storage. Safari otherwise deletes site data after 7 days without a visit; add Slidecko to the home screen or save projects as files to be safe.
- Pending changes are saved the moment the page is hidden or closed, because iOS freezes hidden tabs and has no leave warning.

## Accessibility

**Accessibility check** (View → Check accessibility …, or ⌘K): a panel at the bottom right (on phones at the bottom) lists what makes the presentation hard to use with a screen reader or hard to read, grouped by slide, with a count in its head and on the slide thumbnails. It follows every edit while open. A click on an entry shows its slide and selects the element; quick fixes take one click and Undo takes them back. Hidden slides are not checked.

| Rule | Severity | Quick fix |
| --- | --- | --- |
| Picture without alt text (or with a file name like `IMG_2041.jpg` as alt text) | error | type the alt text right in the entry, or "Mark as decorative" |
| Text contrast below WCAG AA: 4.5:1, or 3:1 for large text (24 px, or 18.66 px bold, on a 980 px wide slide). The background is the box's own fill, else the topmost filled shape, text box or code block under the box's centre (master and layout elements included), else the slide or title bar background of the theme; translucent fills are mixed in. | error | – |
| Text over a picture, or a gradient whose colours under the box fail the contrast | tip (check by eye) | – |
| Text smaller than 16 px (code: 12 px), scaled with the canvas width | warning | – |
| Slide without a title (no "Slide title" mark and no first- or second-level heading) | warning | "Mark as title" on the topmost short text |
| The same title as an earlier slide | tip | – |
| Reading order (the order of the elements, which is also their stacking) differs from top to bottom, left to right, or the title is not read first | warning | "Fix reading order" puts the elements in visual order without changing which of two overlapping elements lies on top; when that is not possible, it is only reported |
| Table without a header row | warning | "Add header row" |
| Link texts like "click here", "here", "more", "hier", "mehr" | warning | – |
| Empty text box (without fill or outline) | tip | "Delete box" |
| YouTube video | tip: check that it has captions | – |

Colours and sizes come from the elements, the theme and the editor's slide CSS; own theme CSS that changes text colours is not taken into account.

**Alt text**: the image properties have an "Alt text" field and a "Decorative" switch. The alt text is written to PowerPoint (`descr`), OpenDocument (`svg:desc`), the HTML presentation and the Slidev project (`alt`); decorative pictures get an empty alt (in PowerPoint also its "Mark as decorative" flag, in Slidev `role="presentation"`). PowerPoint, OpenDocument and Slidev imports read both back. A text box marked as slide title without a heading inside is announced as a heading in the presentation and the HTML export.

Text and buttons reach 4.5:1 contrast (also in dark mode), every control has an accessible name, the command palette is a combobox with a list, and `prefers-reduced-motion` turns animations off. Checked with Lighthouse and axe on the start page and the editor, desktop and mobile.

## Light and dark

The interface follows the system or is fixed to light or dark (sun/moon switch in the footer). `src/scheme.js` sets `<html data-scheme="light|dark">`, which `app.css` reads; the choice is stored under `slides-builder:scheme`, so pages on the same site can share it. Slides keep their theme colours in either mode.

## Languages

English and German. Without a stored choice the browser language decides: German for German browsers, English otherwise. A link with `?lang=de` or `?lang=en` picks the language and stores it like the switch does (under `slides-builder:lang`, so pages on the same site can share it). Switching in the footer works at once, without reloading.

## View in the URL

The project overview (`#home`) or the open project and slide (`#<project>/<slide>`) are in the address hash. Every change is a browser history entry, so back and forward move between overview, projects and slides, and reloads and links open exactly that view. The app's address without a hash opens the last project. What the URL does not hold (selection, folded decks, scroll position, search term) is kept per tab in `sessionStorage` and restored after a reload.
